# רמי אקסטרים · אונליין 🃏

משחק רמי אקסטרים לריבוי שחקנים (עד 4) עם קוד חדר, שרת סמכותי על Cloudflare,
וסנכרון בזמן אמת דרך WebSockets. חינמי לחלוטין לארח.

---

## איך זה בנוי

```
rami-online/
├── index.html            נקודת כניסה (Vite)
├── vite.config.js        הגדרות build
├── wrangler.toml         הגדרות Cloudflare (Worker + Durable Object)
├── package.json
├── src/
│   ├── game-core.js      ← לוגיקת המשחק הטהורה. רצה בשרת (מקור אמת יחיד).
│   ├── releases.js       ← תוכן מסך "מה חדש" (הערות גרסה)
│   ├── worker/
│   │   └── index.js      ← השרת: חדרים, WebSockets, AI, צנזור קלפים
│   └── client/
│       ├── main.jsx      ← אפליקציית React: בית → לובי → משחק
│       ├── ui.jsx        ← רכיבי התצוגה (הקלפים, השולחן, החוקים)
│       └── net.js        ← חיבור WebSocket לשרת
└── tests/
    ├── fake-storage.mjs   ← חיקוי אחסון ה-Durable Object לבדיקות
    ├── host-reconnect.mjs ← בדיקות חיבור מחדש (מארח, כיסאות). `npm test`
    └── room-lifetime.mjs  ← בדיקות סגירת חדר (סיום, ריק, ללא פעילות)
```

**למה שרת?** בגרסה מקומית כל דפדפן מחזיק את כל החבילה — כלומר כל שחקן "רואה"
את הקלפים של כולם. בגרסה האונליין השרת (Durable Object אחד לכל חדר) מחזיק את
מצב המשחק האמיתי ושולח לכל שחקן רק את היד שלו; ידי היריבים מגיעות כמספר קלפים
בלבד. זה מונע רמאות.

## העלאה — שלב אחר שלב

> **חשוב — מבנה המאגר.** הפרויקט יושב בתת-תיקייה `rami-online/` בתוך המאגר
> `mantel`, ולא בשורש המאגר. כל פקודת build/deploy חייבת לרוץ מתוך
> `rami-online/`. זו הסיבה הנפוצה ביותר לפריסה שבורה: אם ה-build רץ משורש
> המאגר הוא לא מוצא `package.json`, ה-build לא מתבצע, ומה שמועלה הוא קוד
> המקור במקום תיקיית `dist` הבנויה — התוצאה היא מסך ירוק ריק.

### 1. העלאה לגיטהאב

```bash
git add .
git commit -m "רמי אקסטרים אונליין"
git push
```

### 2. חיבור ל-Cloudflare

יש שתי דרכים. **דרך ב' (CLI) מומלצת** כי היא פשוטה יותר עבור פרויקט עם
Durable Objects, והיא לא תלויה בהגדרות build בלוח הבקרה.

#### דרך ב' — משורת הפקודה (מומלץ)
```bash
cd rami-online            # ← חובה: הפרויקט הוא תת-תיקייה במאגר
npm install
npx wrangler login        # פותח דפדפן להתחברות לחשבון Cloudflare
npm run deploy            # בונה את הלקוח (vite build) ואז פורס (wrangler deploy)
```

`npm run deploy` הוא `npm run build && wrangler deploy` — הבנייה *חייבת* לרוץ
לפני הפריסה, כי `wrangler.toml` מגיש את התיקייה `./dist` כקבצים סטטיים
ו-`dist/` לא נשמר בגיט (הוא ב-`.gitignore`).

בסיום, wrangler ידפיס את הכתובת:
```
https://mantel.<שם-החשבון>.workers.dev
```

#### דרך א' — דרך לוח הבקרה של Cloudflare (Dashboard)
1. היכנסו ל-[dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages**.
2. לחצו **Create** → **Workers** → **Connect to Git** ובחרו את המאגר.
3. הגדרות build — שלושתן נדרשות:
   - **Root directory:** `rami-online` ← בלי זה הפריסה תישבר
   - **Build command:** `npm run build`
   - **Deploy command:** `npx wrangler deploy`
4. לחצו **Save and Deploy**.

> אם הפרויקט כבר מחובר ל-Git בלוח הבקרה, שימו לב ששתי דרכי הפריסה דורסות זו
> את זו: פריסה ידנית מה-CLI תוחלף בפריסה האוטומטית הבאה מ-Git אם הגדרות
> ה-build שם עדיין שגויות. תקנו את ההגדרות בלוח הבקרה, או נתקו את חיבור ה-Git.

> **הערה על Durable Objects:** הפריסה הראשונה יוצרת אוטומטית את מחלקת ה-`Room`
> (מוגדר ב-`wrangler.toml` תחת `[[migrations]]`).
>
> חשוב: `wrangler.toml` משתמש ב-`new_sqlite_classes` ולא ב-`new_classes`.
> Durable Objects מגובי-KV (`new_classes`) דורשים תוכנית Workers **בתשלום**;
> הגרסה מגובת-SQLite עובדת גם בתוכנית החינמית, ומחלקת `Room` משתמשת רק
> ב-`storage.get`/`storage.put` שנתמכים זהה בשתיהן.
>
> אי אפשר להחליף בין שני הסוגים על מחלקה שכבר קיימת — wrangler יחזיר
> `Cannot apply new_sqlite_classes migration to existing class Room`. אם זה
> קורה, ה-`Room` כבר נוצר כ-KV וצריך למחוק את ה-Worker וליצור אותו מחדש.

## פתרון תקלות

### המסך ירוק וריק ולא קורה כלום

זה אומר ש-`index.html` הוגש בהצלחה אבל חבילת ה-JavaScript לא נטענה, ולכן React
מעולם לא עלה. הרקע הירוק הוא פשוט ה-`background` של ה-`<body>`.

מאז נוספה לדף בדיקה אוטומטית: אם האפליקציה לא עלתה תוך 6 שניות, מוצגת הודעת
שגיאה בעברית עם כתובת הקובץ שנכשל — במקום מסך ירוק שקט.

**איך לאמת בוודאות:** פתחו את הכתובת בדפדפן → `F12` → לשונית **Network** →
רעננו. חפשו את הבקשה ל-JavaScript:

| מה רואים | המשמעות | התיקון |
|---|---|---|
| בקשה ל-`/src/client/main.jsx` עם `404` | הועלה קוד המקור, ה-build לא רץ | הריצו `npm run deploy` מתוך `rami-online/` |
| בקשה ל-`/assets/index-*.js` עם `404` | `dist` ישן/חסר בפריסה | בנו מחדש ופרסו מחדש |
| `/assets/index-*.js` מחזיר `200` אבל עם `Content-Type: text/html` | הגשת קבצים סטטיים לא מוגדרת נכון | ודאו ש-`[assets] directory = "./dist"` ב-`wrangler.toml` |

### הכתובת שקיבלתי מ-wrangler שונה מהכתובת שאני משתמש בה

שם ה-Worker ב-`wrangler.toml` הוא שם המארח. הוא מוגדר כאן כ-`mantel`, כדי
שהפריסה תעדכן את `https://mantel.<שם-החשבון>.workers.dev`. אם תשנו את השם,
תיווצר פריסה חדשה בכתובת אחרת והישנה תמשיך לרוץ.

## פיתוח מקומי (אופציונלי)

צריך שני חלונות טרמינל, כי הלקוח והשרת רצים בנפרד:

```bash
# חלון 1 — השרת (Worker + Durable Object)
npx wrangler dev

# חלון 2 — הלקוח (Vite, עם proxy ל-/api → localhost:8787)
npm run dev
```

פתחו את הכתובת ש-Vite מדפיס (בד"כ `http://localhost:5173`).
פתחו כמה טאבים כדי לדמות כמה שחקנים.

לחלופין, גרסה מאוחדת בפקודה אחת (בונה ואז מריץ הכל דרך wrangler):
```bash
npm run cf:dev
```

## איך משחקים

1. **צור חדר** — הזן שם, לחץ "צור חדר חדש". תקבל קוד בן 4 תווים.
2. **הזמן חברים** — שתף את הקוד או את קישור ההזמנה (כפתור העתקה בלובי).
3. חברים מזינים שם + קוד ומצטרפים לחדר.
4. **המארח** לוחץ "התחל משחק" (צריך לפחות 2 שחקנים; אפשר גם למלא מקומות
   ריקים בשחקני מחשב).
5. משחקים! חוקי המשחק זמינים דרך כפתור 📖 בכל מסך.

**חיבור מחדש:** אם מישהו מתנתק, הוא יכול להיכנס שוב עם אותו שם וקוד ולחזור
למקומו — המשחק ממתין לו.

**סידור היד:** כל שחקן יכול לסדר את הקלפים שלו **בכל רגע** — גם כשזה לא התור
שלו — בגרירה (לחיצה ארוכה על קלף וגרירתו על קלף אחר) או בכפתור 🔀 מיין. הסידור
נשמר בשרת לכל שחקן בנפרד, שורד ניתוק וחיבור מחדש, ואף שחקן אחר לא רואה אותו.
גרירה על קבוצה שעל השולחן (הצמדה) עדיין אפשרית רק בתור שלך.

## הערות גרסה ("מה חדש")

`src/releases.js` הוא המקור היחיד לתוכן המסך. כל כניסה היא גרסה אחת, החדשה
ראשונה. האפליקציה פותחת את המסך פעם אחת אוטומטית לכל שחקן שעדיין לא ראה את
הגרסה הנוכחית (נשמר ב-`localStorage` תחת `rami_seen_release`), ותמיד אפשר
לפתוח אותו שוב מכפתור 🆕 במסך הבית, בלובי, או בראש מסך המשחק.

**בכל שחרור גרסה:**

1. עדכנו את `version` ב-`package.json` (המספר הזה נצרב ל-build ומוצג בפינה).
2. הוסיפו כניסה תואמת בראש `RELEASES` ב-`src/releases.js` — עם אותו מספר גרסה
   בדיוק, אחרת המסך יציג אזהרה שהגרסה שרצה אצל השחקן שונה מזו שמתוארת.
3. `npm run deploy`.

## מגבלות ידועות

- **AI רץ עם `setTimeout`** בתוך ה-Durable Object. זה עובד היטב לחדר פעיל, אבל
  אם *כל* השחקנים האנושיים מתנתקים בזמן שתור ה-AI, ייתכן שהמהלך יידחה עד
  שמישהו יתחבר מחדש. לחדר עם שחקנים אנושיים פעילים — אין בעיה.
- אין התמדה של היסטוריית משחקים בין חדרים (הנקודות נשמרות רק כל עוד החדר חי).
  אם תרצה ליגה/טבלת שיא קבועה — אפשר להוסיף D1 (מסד SQLite חינמי של Cloudflare).
